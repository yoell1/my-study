# 클래스 기초 · 객체 지향 설계 맛보기

> 2026-09-22 · Java 클래스와 객체

## 1. 클래스 기초 개념 정리

### 1-1. 클래스와 객체의 정의

| 용어 | 뜻 | 비유 |
| --- | --- | --- |
| **클래스 (Class)** | 객체를 만들기 위한 **설계도**. 어떤 데이터(필드)와 기능(메서드)을 가질지 정의한다 | 붕어빵 틀 |
| **객체 (Object)** | 설계도를 바탕으로 **실제로 메모리에 만들어진 것** | 틀로 찍어낸 붕어빵 |
| **인스턴스 (Instance)** | 객체와 같은 것을 가리키되, "**어떤 클래스로부터** 만들어졌는가"를 강조할 때 쓰는 말 | "이 붕어빵은 팥붕어빵 틀의 인스턴스다" |

```java
BankAccount woojin = new BankAccount("110-123-456789", "이우진", 100000);
//   ↑ 클래스(타입)   ↑ 참조 변수   ↑ new 로 객체 생성
```

- `new` 가 실행되는 순간 메모리(힙 영역)에 객체가 만들어진다
- 변수 `woojin` 에는 객체 자체가 아니라 **객체가 있는 위치(참조값)** 가 저장된다
- 같은 클래스로 객체를 여러 개 만들어도 **데이터는 각자 따로** 가진다

### 1-2. 클래스 구성 요소

```java
public class BankAccount {

    // ① 필드 — 객체가 가지는 데이터 (상태)
    private String owner;
    private long balance;

    // ② 생성자 — 객체를 만들 때 한 번 실행되어 필드를 초기화
    public BankAccount(String owner, long balance) {
        this.owner = owner;
        this.balance = balance;
    }

    // ③ 메서드 — 객체가 할 수 있는 일 (행동)
    public void deposit(long amount) {
        balance += amount;
    }
}
```

| 구성 요소 | 설명 | 핵심 포인트 |
| --- | --- | --- |
| **필드 (Field)** | 객체의 데이터를 저장하는 변수 | 보통 `private` 으로 숨긴다 |
| **생성자 (Constructor)** | `new` 할 때 호출되어 필드를 초기화 | 클래스 이름과 같고 **반환형이 없다**. 하나도 안 만들면 컴파일러가 기본 생성자를 만들어준다 |
| **메서드 (Method)** | 객체의 기능 | `반환형 이름(매개변수) { ... }` |

#### 함께 알아둘 것

- **`this`** — "지금 이 객체 자신". 매개변수 이름과 필드 이름이 같을 때 `this.owner = owner;` 처럼 구분한다
- **생성자 오버로딩** — 매개변수가 다른 생성자를 여러 개 만들 수 있다. `this(...)` 로 다른 생성자를 호출할 수 있다
- **접근 제한자**

  | 제한자 | 접근 범위 |
  | --- | --- |
  | `public` | 어디서나 |
  | `protected` | 같은 패키지 + 상속받은 클래스 |
  | (default) | 같은 패키지 |
  | `private` | 같은 클래스 안에서만 |

- **캡슐화와 getter / setter** — 필드는 `private` 으로 숨기고, 필요한 만큼만 메서드로 열어준다.
  무조건 getter/setter를 다 만드는 게 아니라, 바꾸면 안 되는 값은 **setter를 일부러 만들지 않는다**
- **`static`** — 객체마다 따로가 아니라 **클래스 전체가 하나를 공유**하는 필드·메서드. `클래스명.메서드()` 로 부른다

## 2. 객체 지향 설계 맛보기 — 은행 계좌

### 2-1. 대상 선정: 은행 계좌

실제 은행 계좌를 보고 "**가지고 있는 것**"과 "**할 수 있는 일**"을 나눴다.

| 실제 계좌 | 클래스로 옮기면 |
| --- | --- |
| 계좌번호, 예금주, 잔액 | 필드 `accountNumber`, `owner`, `balance` |
| 계좌 개설 | 생성자 `BankAccount(...)` |
| 입금 / 출금 / 이체 / 조회 | 메서드 `deposit()`, `withdraw()`, `transfer()`, `printInfo()` |
| 은행 전체 계좌 수 | `static` 필드 `accountCount` |

### 2-2. 설계하면서 고민한 점

1. **잔액은 밖에서 직접 못 바꾸게** — `balance` 를 `private` 으로 두고 `setBalance()` 는 만들지 않았다.
   잔액이 바뀌는 길은 `deposit()` / `withdraw()` 두 개뿐이라, 음수 입금이나 잔액 초과 출금을 **한 곳에서** 막을 수 있다.
2. **이체는 객체끼리 협력** — `transfer(BankAccount target, long amount)` 는 다른 계좌 **객체를 매개변수로** 받는다.
   출금이 성공했을 때만 상대 계좌에 입금한다.
3. **계좌 수는 `static`** — 계좌 하나하나가 아니라 은행 전체의 정보라 모든 객체가 공유한다.

### 2-3. 코드

- [`src/BankAccount.java`](src/BankAccount.java) — 설계도 (클래스)
- [`src/BankMain.java`](src/BankMain.java) — 객체를 만들어 사용하는 실행 클래스

```java
// BankMain.java 중 일부
BankAccount woojin = new BankAccount("110-123-456789", "이우진", 100000);
BankAccount friend = new BankAccount("220-987-654321", "김철수");   // 잔액 0원

woojin.deposit(50000);
woojin.withdraw(500000);          // 잔액 부족 → 실패
woojin.transfer(friend, 70000);   // 객체끼리 협력

// woojin.balance = 999999999;    // 컴파일 에러 — private 이라 직접 접근 불가
```

## 3. 한 줄 정리

> 클래스는 **설계도**, 객체는 설계도로 **찍어낸 실물**이다.
> 좋은 설계는 데이터를 숨기고(`private`), 바꾸는 길을 메서드로 좁혀서 **잘못된 값이 들어올 틈을 없애는 것**이다.
